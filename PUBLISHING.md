# Publication and maintenance

## Release scope

The owner authorized the portfolio release, profile release, and creation of the public **carsonmcrae/southern-surface-case-study** repository on October 22, 2026.

This repository contains only original case-study documentation and artwork. The executable prototype lives in the portfolio repository. The production application's source, history, customer data, credentials, and operational configuration are excluded.

## Release procedure

1. Merge and publish the reviewed portfolio changes, then verify the case study, prototype, artwork, and crosslinks at their public destinations.
2. Merge the reviewed GitHub profile changes after the portfolio release.
3. Create the public standalone repository from this reviewed documentation bundle with a fresh history. Inspect every staged file before its first public push.
4. Verify the standalone repository is publicly reachable, then connect the verified repository link from the portfolio and profile where applicable.
5. Check the rendered README, artwork, relative documentation links, portfolio links, prototype link, and business website link after publication.

This procedure describes the release order; it is not itself a deployment success log. Public destinations must be checked directly after each release step. No production application deployment, database operation, secret, or infrastructure change is needed for this static showcase.

## Maintenance checks

- Keep the owner's October 22, 2026 report labeled **owner-reported**: 150 new leads generated and 5 jobs secured with the system last month. Do not infer exact reporting dates, revenue, a common cohort, or a conversion rate.
- Keep every prototype record fictional and every browser interaction separate from production systems.
- Review new writing, artwork, staged contents, and commits for private source, customer information, credentials, privileged links, and operational configuration.
- Recheck local Markdown links and the SVG's self-contained structure after documentation or artwork changes.
- Run the relevant prototype and browser checks in the portfolio repository when its implementation changes; retain the limits documented in [Validation scope](docs/validation.md).
- Verify public links after release. A working local preview does not establish that a published destination is available.
